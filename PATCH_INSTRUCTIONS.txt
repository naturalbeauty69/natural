STUDENT + STAFF SELF-REGISTRATION / APPROVAL PATCH

This patch adds:
- /register page with Student or Staff account request.
- email + password registration via Supabase Auth.
- pending approval state.
- /pending-approval page.
- login routing based on approved profile role.
- owner/director approval queue in Admin > Users.
- optional course assignment when approving a Student.
- automatic linking/creation of the students.profile_id record when a Student is approved.
- approval protection so ordinary users cannot change role/approval/security fields themselves.
- pending/rejected/suspended accounts cannot enter /admin or /student.

DEPLOYMENT ORDER
1. Back up your current working website/GitHub state.
2. In Supabase SQL Editor, run ONLY:
   SUPABASE_STUDENT_STAFF_APPROVAL_MIGRATION.sql
3. Verify the returned approval_status/requested_role counts.
4. In GitHub, replace ONLY the files in this ZIP using the same relative paths.
5. Deploy to Cloudflare.
6. Test with a brand-new TEST email address.

TEST FLOW
A. Open /register?role=student
B. Register using a test email.
C. You should see "Approval pending".
D. Owner/Director opens Admin > Users.
E. Pending request appears.
F. Select the course (optional) and click Approve.
G. Student can now log in and access authorized Academy resources.
H. Open /register?role=staff and repeat for a staff test account.
I. Approve as Staff; the account can then enter the Admin area according to its staff role.
J. Test Reject and Suspend with a test account.

IMPORTANT
- Do not re-run the full schema.sql.
- Do not delete existing users/profiles.
- Existing active accounts are backfilled as approved so the current site keeps working.
- Only owner/director can approve/reject/change role.
- A Student approval may optionally create/link their row in public.students and assign course_id.
- This patch does not change product data or Academy resource files.
